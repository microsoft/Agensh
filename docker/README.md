# Deployment configuration

Compose overlays and host configuration for the released single-node team
and standalone baseline. The team base is generated by
[`tools/gen_compose_prod.py`](../tools/gen_compose_prod.py) as ignored
`_gen_prod.<profile>.yml`; [`Makefile`](../Makefile) applies the team overlay.
The generator takes worker mounts, the prompt directory and the board id from
the profile's task pack (`AGENSH_PACK`, default `programbench`), and worker
resources from `WORKER_MEMORY` and `WORKER_CPUS`.

| Path | Purpose |
|---|---|
| `docker_compose.team.yml` | Team network isolation, model egress proxy and MySQL TCP health check |
| `network_open.yml` | Added after the team overlay when the network mode is `open`: the default network gets general egress |
| `network_allowlist.yml` | Added when the network mode is `allowlist`: the `egress-filter` proxy joins the egress bridge, and workers (given `HTTP(S)_PROXY` by the generated Compose) reach only package registries and the project's `allow_domains`; decisions are logged to `$DATA_ROOT/<profile>/egress/egress.jsonl` |
| [bootstrap/](bootstrap/) | One-shot Gitea/Mattermost account and token provisioning |
| [nginx-edge/](nginx-edge/) | Host-facing HTTP routes for repository and chat services |
| `agensh.slice` | Host cgroup ceiling: 80% memory, no swap and an aggregate task limit |
| `agensh_reboot_guard.service` | Installs the `agensh-reboot-guard.service` unit to stop running `omcgitea-*` Compose projects after a host reboot |

The generated team base defines shared services and one worker/router pair
per agent. Bootstrap completes before workers start. Each worker has private
HOME, token and socket mounts; MySQL stores events and board history. The
default network is internal, the model proxy also joins `egress`, and the
edge proxy also joins `edge` for host access.

Team environment comes from `.env.<profile>`. The standalone launcher supplies
its own project, image, path and subnet variables to the standalone Compose
file, [`tasks/programbench/docker/single_agent.yml`](../tasks/programbench/docker/single_agent.yml). Its `/workspace` and `/work` mounts point to the same source tree so
the common archive bridge can save it.

Use `make help` at the repository root for team lifecycle commands.
`make down PROFILE=…` preserves data; `make clean PROFILE=…` deletes that
profile's data. Host guard installation and launch prerequisites are in the
[reproduction guide](../REPRODUCE.md#prerequisites).

The reboot guard assumes matching projects are orphaned after boot; it does
not test driver liveness or restrict matches to this checkout. Use
`AGENSH_GUARD_DRY_RUN=1 bash scripts/agensh_reboot_guard.sh` to inspect its scope
before invoking it manually.

## Bootstrap

`bootstrap/bootstrap.sh` runs after service health checks and administrator
creation. Generated Compose supplies comma-separated `AGENTS` and `REPOS`.
The script creates the organization and `coders` team, synchronizes passwords,
installs CODEOWNERS, disables worker auto-watching and obtains an Actions runner
token. Coders can merge PRs with zero required approvals; direct pushes to
`main` are restricted to the administrator.

Credentials are cached privately under `$BOOTSTRAP_DATA_DIR/tokens`. Valid
tokens are reused and stale tokens rotated. Routers read Gitea passwords for
SSE login; the token service supplies API tokens. `.bootstrap-done` skips
completed provisioning. `make bootstrap-rerun PROFILE=…` removes that marker;
`AGENSH_BOOTSTRAP_FORCE=1` works when set inside the bootstrap container and is
not forwarded automatically from the host. The task runner seeds the repository
and creates the private task channel after bootstrap.

## Edge routes

`nginx-edge/nginx.conf` sets the connection limits, 100 MiB request limit and
virtual-host includes. `conf.d/gitea.conf` routes container port 80 to
`gitea:3000` with unbuffered HTTP/1.1 for SSE and Git. Git pushes
(`git-receive-pack`) have no size limit, because the task runner pushes a whole
imported history through this port; Gitea authenticates them. `conf.d/mattermost.conf`
routes port 81 to `mattermost:8065`, preserving WebSocket upgrades and long-lived
connections. Both are default servers and forward client/host headers; profile
variables determine host port mappings. Compose mounts the configuration
read-only, and internal workers use the upstream service names directly.
